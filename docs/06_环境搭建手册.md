# 06 · 环境搭建手册（傻瓜版 · 换机器通用）

> 版本：v1.0（2026-11-11）｜适用：任意一台「Linux + NVIDIA GPU」的机器（本手册在 A800 上实测通过）
> 目标读者：**没做过这个项目、也不懂 CUDA 的人**，照着敲命令就能把环境搭好并跑出初步评测。
> 配套脚本：`工作区/40_工具/setup/check_env.sh`（体检）、`setup_env.sh`（一键装）
> 全过程实测：**约 40–60 分钟**（主要耗在下载 torch 2.5 GB + TensorRT 2.1 GB）

---

## 0. 这份手册能带你到哪

跟着做完，你会得到：

1. 一个能用的基线环境（TensorRT 8.6 + torch + 编译好的 cudacall）；
2. 一次**能跑通的全链路评测**（先用"假数据+假模型+假解码"验证流程，结果为 `MODE=FAKE`）；
3. 等客户交了真模型/真库/真数据，**只改 3 行路径**就能出真基线（`MODE=REAL`）；
4. 一份按规范生成的评测报告（格式见 `docs/05_评测报告格式规范.md`）。

**先记住一句话**：这个项目现在"缺的不是环境，是甲方的 3 个文件"（`.engine` / `.so` / `.ccf` 数据）。所以本手册的最后一步一定会停在 `MODE=FAKE`，这是**正常的**，不是你没搭好。

## 1. 你需要准备什么

| # | 东西 | 说明 | 没有怎么办 |
|---|---|---|---|
| 1 | 一台 Linux GPU 机器 | Ubuntu 20.04/22.04 最佳；NVIDIA 卡（A800/A100/4090 都行）；**至少 50 GB 空闲磁盘** | 找运维/客户要 |
| 2 | 登录方式 | 用户名+密码（或密钥）；如果是跳板机，还需要跳板机地址和端口 | 找给你机器的人要 |
| 3 | 能用的一整天 | 首次搭建 40–60 分钟（主要在下载） | 分两次也行，脚本可断点续跑 |
| 4 | 工作区文件 | 本项目的 `工作区/10_源码`（源码）与 `工作区/40_工具`（脚本） | 就在本项目目录里，不用另外找 |
| 5 | 外网或内网源 | 能访问 pypi（清华源）、NVIDIA 下载站、内网 apt 源 | 让客户开代理或给内网镜像 |

**先确认一件事**：这台机器上有没有别的客户任务在跑？如果有（像 A800 上 7 张卡在跑 vLLM），**只挑一张空闲卡用，绝对不要 kill 别人的进程、不要重启 docker**。脚本会自动挑最空闲的卡。

## 2. 整体流程（先看懂再动手）

```
本地 Windows                        目标 Linux GPU 机器
─────────────                       ────────────────────
① 传源码 + 脚本  ──── ssh/scp ────►  ② 体检 check_env.sh
                                      ③ 一键搭建 setup_env.sh
                                        ├ 装 libsodium（apt）
                                        ├ 建 venv + 装 torch
                                        ├ 下 TensorRT 8.6
                                        ├ 解包源码
                                        ├ 编译 stub 解码 + 加密工具
                                        ├ 编译 cudacall
                                        ├ 造假数据/假模型并加密
                                        └ 生成 baseline.env
                                      ④ 跑初步评测（MODE=FAKE）
                                      ⑤ 换真件 → MODE=REAL（等甲方）
```

## 3. 第 0 步：本地准备（Windows 上做）

> 目的：把源码和脚本传到 GPU 机器的 `~/sandai_baseline/upload/`。

**3.1 打开 PowerShell，进入项目目录**

```powershell
cd ~/sandai
```

**3.2 设置登录信息（把尖括号换成真实值）**

```powershell
# 如果目标机器有跳板（像 A800）：
$env:JUMP_PASS = '<跳板密码>'
$env:SSH_PASS  = '<目标机器密码>'
$env:PYTHONPATH = '~/sandai\.tools\py'

# 如果没有跳板，直连：
$env:SSH_PASS  = '<目标机器密码>'
$env:PYTHONPATH = '~/sandai\.tools\py'
```

**3.3 传源码包（约 0.5 MB）**

```powershell
$py = 'C:\Users\liuguang1\.dsh\dsh-runtimes\dsh-primary-runtime\dependencies\python\python.exe'

# 有跳板（示例参数按需替换）
& $py '工作区\40_工具\remote\ssh_put.py' `
  --jump-host <JUMP_HOST> --jump-port 9090 --jump-user <jump_user> `
  --host <GPU_HOST> --port 22 --user <用户名> `
  --local '工作区\10_源码\baseline_cuda_ms_basecall-main' `
  --remote '/home/<用户名>/sandai_baseline/upload/ms_basecall-main.tar.gz'

# 无跳板：去掉 --jump-* 三个参数即可
```

**3.4 传工具包（源码 + 脚本 + 评测规范，约 50 KB）**

```powershell
foreach ($d in '工作区\40_工具\baseline','工作区\40_工具\setup','工作区\40_工具\report') {
  $name = Split-Path $d -Leaf
  & $py '工作区\40_工具\remote\ssh_put.py' `
    --jump-host <JUMP_HOST> --jump-port 9090 --jump-user <jump_user> `
    --host <GPU_HOST> --port 22 --user <用户名> `
    --local $d --remote "/home/<用户名>/sandai_baseline/tools/$name.tar.gz" `
    --extract --extract-to '/home/<用户名>/sandai_baseline/tools'
}
```

> 期望输出：每次最后能看到 `exit: 0`。若报 `CONNECT_FAIL`，检查密码/跳板参数（见 §10 错误 E1）。

## 5. 第 2 步：先体检（重要！先跑这个）

```bash
bash ~/sandai_baseline/tools/setup/check_env.sh
```

**看输出，只关心 `[FAIL]` 行**：

- 全是 `PASS`/`WARN` → 继续第 3 步；
- 有 `[FAIL]` → 按下面处理：

| FAIL 项 | 处理命令（Ubuntu） |
|---|---|
| 缺 gcc/g++/make | `sudo apt install -y build-essential` |
| 缺 cmake | `sudo apt install -y cmake`（或问运维装 3.18+） |
| 缺 git | `sudo apt install -y git` |
| 缺 venv | `sudo apt install -y python3-venv` |
| 缺 nvcc / 无 /usr/local/cuda | 让运维装 **CUDA Toolkit**（本机是 12.4；驱动 ≥525 才支持 CUDA 12） |
| 缺 cuDNN 头/库 | 让运维装 cuDNN（本机自带 8.9.7） |
| 无 nvidia-smi | 机器没有可用 GPU 或驱动没装 → 找运维 |
| 网络不可达 | 问客户要代理/内网源 |

## 6. 第 3 步：一键搭建（核心，一条命令）

```bash
bash ~/sandai_baseline/tools/setup/setup_env.sh
```

- 第一次跑：**约 40–60 分钟**，大部分时间在下载（torch 2.5 GB、TensorRT 2.1 GB）。
- 断了/报错：修好后**再跑同一条命令**，已完成的步骤会自动跳过（脚本是幂等的）。
- 不想用 sudo 装系统库：加 `--skip-apt`（前提是 libsodium 已装）。
- 想指定卡：加 `--gpu 4`；完全不指定则自动挑最空闲的卡。

## 7. 第 4 步：跑初步评测（用假件验证链路）

> 目的：在等甲方文件期间，先证明「整条流水线是通的」。
> 做法：把配置临时指向假数据/假模型/假解码库，跑一次，应看到 `MODE=FAKE` 且 `exit=0`。

**照抄下面 4 行**：

```bash
B=~/sandai_baseline/tools/baseline
sed -i 's#models/real/#models/fake/#' $B/baseline.env
sed -i 's#libs/real#libs/stub#'       $B/baseline.env
sed -i 's#data/real/#data/fake/#'     $B/baseline.env
bash $B/run_baseline.sh
```

**期望输出（A800 实测）**：

```
MODE=FAKE
[RESULT] OK 但为 FAKE 模式：结果只能证明链路通，不可作为性能/精度基线
[info] RTABasecall Version: v0.1.3
[info] set gpu_device_id 0
[info] Loaded engine size: 19 MiB
[info] InitializeCudaCall Success !!!
[info] cost time: 20.1 ms   (×10 轮)
[info] basecall Speed: 60.5 M samples/sec, 20.146711
[run] exit=0
报告: ~/sandai_baseline/baseline/<时间戳>/baseline_report.md
```

**这一步的判定标准**：只要 `MODE=FAKE` + `exit=0` + 生成了 4 个 npy，就算**环境搭建成功**。那个 `60.5 M/s` 是假数据+假模型跑出来的，**没有任何性能含义**，别拿去汇报。

生成的东西在哪：

```
~/sandai_baseline/baseline/<时间戳>/
├─ baseline_report.md      ← 报告
├─ chunk_type.npy  moves.npy  sequence.npy  qstring.npy   ← 4 个输出
└─ run.log                 ← 原始日志
```

## 8. 第 5 步：等真件到位 → 出真基线（只改 3 行）

甲方把 3 样东西给你后（**这是目前唯一的外部阻塞**，见 `docs/04` 的 C-01~C-04）：

| 甲方给的东西 | 你放到哪 |
|---|---|
| 加密的 `.engine`（至少 sup 档） | `~/sandai_baseline/models/real/`（文件名保持原样） |
| `libfast_decode.so` | `~/sandai_baseline/libs/real/lib/` |
| 测试数据转成的 `.npy`（需先按格式规范转换） | `~/sandai_baseline/data/real/` |

然后：

```bash
B=~/sandai_baseline/tools/baseline
# 1) 先校验：必须显示 MODE=REAL
bash $B/verify_inputs.sh $B/baseline.env

# 2) 跑真基线
bash $B/run_baseline.sh

# 3) 看报告
cat $(ls -dt ~/sandai_baseline/baseline/2* | head -1)/baseline_report.md
```

**判定**：`verify_inputs.sh` 显示 `MODE=REAL` 且 `[RESULT] OK（REAL）`；`run_baseline.sh` 出的报告才能作为真基线。报告格式按 `docs/05_评测报告格式规范.md` 补全（精度段需要 4090 参考 + 对拍脚本）。

## 9. 换新机器：差异检查表（最重要的一页）

换机器**不用改脚本**，但下面 6 件事要核对一遍：

| # | 检查项 | 怎么查 | 不匹配会怎样 | 怎么办 |
|---|---|---|---|---|
| 1 | **GPU 算力 SM** | `nvidia-smi --query-gpu=compute_cap --format=csv` | 编译参数写死 80 编出来的 so 在别的卡上跑不了（`no kernel image`） | 脚本自动取 SM 传给 `-DSM`；驱动太老报不出来时按型号兜底（A800/A100→80，H800/H100→90，4090→89） |
| 2 | **驱动 → CUDA 上限** | `nvidia-smi` 右上角 `CUDA Version` | 驱动低于 CUDA Toolkit 要求 → nvcc 编不出/跑不了 | 驱动 ≥525 支持 CUDA 12；否则让运维升级驱动 |
| 3 | **CUDA Toolkit 版本** | `/usr/local/cuda/bin/nvcc --version` | 与 TensorRT 版本不配套 | TRT 8.6 有 CUDA 11.8 / 12.0 两版，脚本按 nvcc 主版本自动选 |
| 4 | **torch 与 Python 版本** | `python3 --version` | torch 2.4.1 支持 py3.8–3.12；py3.13 需换更高 torch | 脚本自动取 `cpXXX` 标签去取对应 wheel |
| 5 | **cuDNN** | `ls /usr/include/cudnn*.h` | 缺头文件 → cmake 报 `Could NOT find CUDNN` | 让运维装 cuDNN（8.9/9.x 都行） |
| 6 | **磁盘** | `df -h ~` | <50G 会在装 torch/TRT 时爆盘 | 清理或换更大分区；`--root` 指定到大盘 |

**版本配套速查**：

| 组件 | 本项目已验证组合 | 可接受范围 |
|---|---|---|
| CUDA Toolkit | 12.4 | 11.8 / 12.x |
| 驱动 | 560.35.03 | ≥525（支持 CUDA 12） |
| TensorRT | **8.6.1.6** | **必须 8.6.x**（源码用 `executeV2`，TRT 10 已删这个 API） |
| torch | 2.4.1+cu121 | 2.x（py3.8–3.12 对应 wheel） |
| Python | 3.8 | 3.8–3.12 |
| GPU | A800-80G | 任意 sm_70+ NVIDIA 卡（4090 也可，SM 不同） |

> 新机器上如果**没有内网 apt 源**，`libsodium-dev` 装不上，可改为源码编译：
> ```bash
> cd ~/sandai_baseline && curl -LO https://github.com/jedisct1/libsodium/releases/download/1.0.22-RELEASE/libsodium-1.0.22.tar.gz
> tar xf libsodium-1.0.22.tar.gz && cd libsodium-1.0.22 && ./configure --prefix=$HOME/sandai_baseline/libs/sodium && make -j && make install
> # 然后 setup_env.sh 时 cmake 里把 -DSODIUM_DIR 指向该目录（脚本预留了位置）
> ```

## 10. 常见错误 20 条（症状 → 原因 → 解决）

| # | 症状 | 原因 | 解决 |
|---|---|---|---|
| **E1** | `CONNECT_FAIL` | 密码错/跳板参数错/端口错 | 确认跳板是 9090、机器是 22；先手动 ssh 一次确认 |
| E2 | `ssh: Connection closed` | 把 HTTP 端口当 SSH 端口 | 9090 是跳板 SSH；目标机 9090/9091/9092 是 HTTP 服务，别连错 |
| E3 | cmake 报 `Could NOT find CUDNN` | 缺 cuDNN 头文件 | `ls /usr/include/cudnn*.h`；没有就找运维 |
| E4 | cmake 报 `Could NOT find FastDecode` | stub 库没编 | 先跑 setup 的第 7 步（脚本会自动做） |
| E5 | cmake 报 `Could NOT find Sodium` | libsodium 没装 | `sudo apt install libsodium-dev` |
| E6 | cmake 报 `Could NOT find Torch` | torch 没装好 / 用了系统 python | 确认 `~/sandai_baseline/venv/bin/python -c "import torch"` |
| E7 | 编译报 `no kernel image is available` | `-DSM` 与卡不匹配 | 用 `check_env.sh` 看 SM，重跑 setup（脚本自动传） |
| E8 | TensorRT 下载得到一个 HTML 文件 | 用了 `developer.download.nvidia.com/.../secure/...`（返回同意页） | **必须用** `developer.nvidia.com/downloads/...`（脚本已内置正确 URL） |
| E9 | TensorRT 解包报 `not in gzip format` | 同上，下到了 HTML | `rm` 掉重下（脚本会检测 `file` 类型） |
| E10 | torch 下载卡住 | 走 `download.pytorch.org` 太慢 | 不用管，脚本走清华源 + 断点续传；仍失败就重跑（会续传） |
| E11 | 安装 wheel 报 `BadZipFile` | 下载被截断 | 重跑安装脚本（会校验+重下）；或删除 `wheels/` 里对应文件重跑 |
| E12 | `libcupti.so.12: cannot open shared object file` | nvidia-cupti wheel 没装上 | 重跑 setup 第 4 步（离线安装会补齐） |
| E13 | `gpu_device_id is wrong: 4` | `CUDA_VISIBLE_DEVICES=4` 后程序只看到 1 张卡，却传了逻辑号 4 | 传 **逻辑号 0**（`GPU_ID=0`）；setup 生成的 env 已正确 |
| E14 | `python3: command not found` | 没装 python | `sudo apt install python3` |
| E15 | `venv` 创建失败 | 缺 python3-venv | `sudo apt install python3-venv` |
| E16 | 编译到 `test_reload_engine` 失败 | **已知问题**：旧 sample 用 3 参数 `Init()`，当前头文件 4 参数 | 不影响基线，忽略；要修就改该 sample |
| E17 | `run_baseline.sh: 权限不够` | 脚本没执行位 | `bash 脚本路径` 调用即可（不要 `./`） |
| E18 | 跑起来 OOM（显存不足） | 卡被占满 / batch 太大 | `nvidia-smi` 看空闲卡；换空闲卡或降 batch |
| E19 | `MODE=FAKE` 但想要真基线 | 配置还指向假件 | 放真件到 `real/` 目录并恢复 3 行路径（§8） |
| E20 | 报告里性能数字好得离谱（60 M/s） | 假件数据，没有真实计算量 | 正常；`MODE=FAKE` 的数字禁止汇报 |

| 参数 | 作用 |
|---|---|
