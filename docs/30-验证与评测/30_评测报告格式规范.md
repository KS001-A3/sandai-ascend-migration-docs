## 1. 为什么不能只看吞吐

单卡吞吐只是"能不能卖"的一个数；验收真正会卡的是：

| 风险 | 只看吞吐会漏掉什么 |
|---|---|
| 结果不可信 | 没有与 4090 的**逐 read 对拍**，跑得再快也没意义（合同：Modal identity diff < <ACC_TARGET>） |
| 质量下降 | 吞吐达标但 qstring 平均质量偏移（合同：Q_Read_Mean diff < <Q_TARGET>） |
| 假达标 | 计时口径（10^6 vs 2^20）、warm-up、单轮 vs p95、是否含 D2H 同步，都能让数字虚高 5%~30% |
| 换机器就废 | 没有环境指纹（驱动/CUDA/TRT/GPU 型号），结果无法复现 |
| 抖动没测 | 办公机器共享 GPU，均值好看但 p95 延迟爆掉 |
| 精度漂移 | 同一输入跑 3 次结果是否 bit 级一致（run-to-run）没测 |

**所以报告要回答三个问题**：① 结果对不对（精度）② 跑得多快、多稳（性能+稳定性）③ 凭什么信（环境指纹+输入校验+复现命令）。

## 2. 报告结构（固定 6 段，缺段即无效）

| 段 | 标题 | 必须包含 | 判定作用 |
|---|---|---|---|
| **R0** | 环境与输入指纹 | 主机、GPU 型号/编号/驱动、CUDA/TRT/torch 版本、代码版本(`libsandai-basecall.so` sha256)、engine/so/data 的 sha256、`MODE=REAL/FAKE`、时间 | 可复现性的前提；`MODE=FAKE` 直接判报告无效 |
| **R1** | 功能正确性 | Init 成功、单轮跑通、4 个输出 npy 形状/元素数、错误码路径抽样、是否 exit≠0 | 功能不过，后面不看 |
| **R2** | 精度 | 与参考结果的 6 类指标 + 分物种/分档位细分 + 3 次 run-to-run | 合同硬门槛 |
| **R3** | 性能 | 吞吐（双口径）、单轮延迟分布、分段耗时、显存/利用率、batch×T 扫描、与 4090 比值 | 合同硬门槛 |
| **R4** | 稳定性与资源 | 短时 soak（如 30–60 min）显存/吞吐漂移、温度/功耗、异常恢复 | 7 天 soak 的前哨 |
| **R5** | 结论与门槛判定 | 每项 PASS/FAIL/CONDITIONAL + 一句话结论 + 遗留问题清单 | 给决策人看 |

## 3. 指标体系

### 3.1 精度指标（R2）

| ID | 指标 | 定义（建议口径，**待 HDJY 确认**） | 门槛 | 数据来源 |
|---|---|---|---|---|
| P-01 | **Modal identity rate diff** | 对每条 read 计算 mapping identity（匹配碱基数/比对长度），取全体 read identity 的**众数**（modal）；`diff = \|NPU_modal − 4090_modal\|`（百分点） | **< <ACC_TARGET>** | 需 4090 参考 + 比对链路（阶段二/验收阶段） |
| P-02 | **Q_Read_Mean diff** | 每条 read 的 qstring 均值，再对全部 read 取均值；`diff = \|NPU_mean − 4090_mean\|` | **< <Q_TARGET>** | 同上 |
| P-03 | sequence 一致率（逐位） | 同 read 同位置碱基相同的比例（含长度惩罚：长度不一致按编辑距离处理） | ≥ 99.9%（V0 基线口径） | NPU vs 4090 npy |
| P-04 | qstring 平均绝对差 | 逐位 `\|q_npu − q_4090\|` 的均值（仅对齐位置） | ≤ 0.5（V0 口径） | 同上 |
| P-05 | moves 一致率 | 逐 chunk moves 数组逐字节相等比例 | 100%（解码确定性要求） | 同上 |
| P-06 | chunk_type 一致率 | 逐 chunk 分类完全一致比例 | 100% | 同上 |
| P-07 | run-to-run 稳定性 | 同输入连续 3 次，输出 npy 的 sha256 是否全等 | 3/3 相同 | 本机自测 |
| P-08 | 分物种/分档位细分 | P-01~P-06 按 <M> 物种、按 fast/hac/sup 分别给出 | 无单项显著劣化 | 聚合 |

> **关键提醒**：P-01/P-02 需要「mapping + 参考基因组」链路（参考基因组、minimap2、identity 计算脚本），这属于**验收评测**范畴，需 HDJY 给口径与参考版本；P-03~P-07 是团队自己能立刻做的中间层对拍。

### 3.2 性能指标（R3）

| ID | 指标 | 定义 | 门槛 | 备注 |
|---|---|---|---|---|
| S-01 | **吞吐（十进制）** | `samples / elapsed_seconds / 1e6`，samples = batch×chunk×iters | **≥ <PERF_TARGET> samples/s** | 合同口径，**以这个为准** |
| S-02 | 吞吐（2^20，兼容） | 仓库原口径 `/1024/1024` | 参考值 | 比 S-01 高 ~4.86%，报告须同时给，禁止只用它 |
| S-03 | 单轮延迟 | 每次 Basecall 的 ms 值：mean / p50 / p95 / p99 / max | 报告展示，不单独设门槛 | 共享机器必须看 p95 |
| S-04 | 分段耗时 | encode / decode / reads_verification / clip 占比 | 报告展示 | 用 NVTX/事件计时扩展 |
| S-05 | 显存峰值 | `torch.cuda.max_memory_allocated` + `nvidia-smi` 采样 | 报告展示，须 < 卡容量 80% | 防 OOM 风险 |
| S-06 | GPU 利用率 | `nvidia-smi` 1s 采样均值/峰值 | 报告展示 | 判断是否瓶颈在 CPU/拷贝 |
| S-07 | batch×T 扫描 | batch∈{1,32,128,256}，T∈{1000}（及 sup 实测 T） | 报告展示 | 看扩展性与小批性能 |
| S-08 | 相对 4090 比值 | `NPU_throughput / 4090_throughput`（同数据同参数） | 报告展示 | 阶段二用；一阶段给 GPU 内部基线 |
| S-09 | 冷/热启动差异 | 首轮 vs 稳态（剔除前 2 轮） | 报告展示 | 防 warm-up 假象 |

**计时口径约定（必须写进报告头）**：剔除前 2 轮 warm-up；每次 Basecall 前后 `cudaEvent` 计时并 `synchronize`；报告 iterations 与 batch；M 的定义双列。

### 3.3 稳定性指标（R4）

| ID | 指标 | 定义 | 说明 |
|---|---|---|---|
| T-01 | 吞吐漂移 | soak 期间每 5 分钟吞吐，`(max−min)/mean` | < 5% 视为平稳 |
| T-02 | 显存漂移 | 显存峰值随时间增长 | 持续增长 = 泄漏嫌疑 |
| T-03 | 异常恢复 | 注入坏 engine/坏输入/设备忙 → 返回码且不退出进程 | 合同硬性条款 |
| T-04 | 7 天 soak | 168h 无泄漏/死锁/崩溃 | 阶段二/验收前完成 |

## 4. 判定规则

| 结论 | 条件 |
|---|---|
| **PASS** | R0 为 `MODE=REAL` 且输入 sha256 与清单一致；R1 全通过；R2 合同两指标达标；R3 S-01 达标；R4 T-01/T-02/T-03 通过 |
| **CONDITIONAL** | 精度达标但性能未达；或性能达标但精度口径待确认；或有已知限制（如只测 sup 档） |
| **FAIL** | `MODE=FAKE`、输入校验不符、R1 有失败、或任一合同硬指标超差且无法归因 |
| **INVALID** | 缺 R0/R1/R5 任一段，或未附复现命令与输入清单 |

门槛来源：`委托方验收标准.txt:25-31`（性能 <PERF_TARGET>、Modal identity < <ACC_TARGET>、Q_Read_Mean < <Q_TARGET>）。C-06/C-07 未确认前，报告结论标 `CONDITIONAL`。

## 6. 执行矩阵（真基线要跑多少组）

| 维度 | 取值 | 目的 |
|---|---|---|
| 物种 | <M> 物种（各物种），按合同 <N> 条 | 验收覆盖（注意：不是 <M> 物种） |
| 档位 | sup 必跑；fast/hac 视 C-04 范围 | 三档是否全要待确认 |
| batch | 256（生产默认）+ 1/32/128（扩展性） | S-07 |
| iterations | ≥20（去掉 2 轮 warm-up 后取稳态） | S-03 |
| 重复 | ≥3 次（run-to-run） | P-07 |
| 参考机 | 4090（合同基准）；A800 仅内部对照 | P-01/P-02 |
