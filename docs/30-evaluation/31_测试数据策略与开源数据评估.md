## 1. 结论先行

| 问题 | 结论 | 一句话依据 |
|---|---|---|
| **代码里有测试数据吗** | **没有，一条都没有** | 交付仓 245 个文件里 **0 个数据文件**（无 `.npy/.fast5/.pod5/.ccf/.engine`）；6 个 `samples/*.cpp` + 2 个 `python_wrapper/test_*.py` 全是"壳"，只从命令行/固定路径读外部文件；唯一自带的"兜底"是 `np.random.randn` |
| **能自己造（合成）吗** | **能，但必须按质控契约造；我们上一版造错了** | 假基线 256/256 个 chunk 全部 `chunk_type=0`（未过质控）；根因见 §3，生成器已升级 v2 并自测 5 个种子 100% 通过 |
| **能用行业开源数据吗** | **能，但分三层：工程/性能/解码 golden 可用；验收精度不可用、也不能替代甲方数据** | 验收合同 §3.1 明确"数据由甲方提供、以 MD5 定唯一性"；精度指标是"同数据 4090 vs NPU 的差值"，开源数据没有这条证据链 |
| **现在最该做** | ① P0：用 v2 数据重跑假基线，让"链路通"名副其实；② P1：pod5→npy 转换器骨架 + 1 个公开小样本；③ P1：接 openfish 预计算 blob 作解码 golden；④ P2：把"归一化/采样率/chunk 规则"写进索取单 | 见 §7，前三项不依赖任何甲方新输入 |

**总体判断**：开源数据是**有价值的工程替代品**，但**不是验收替代品**。它的最大价值不在"跑分"，而在三件事：**覆盖 chunk_type=1 的真实分布分支**、**给解码器一个独立的金标准**、**让精度对拍脚本（P-03~P-07）提前可测**。

## 3. 现有合成数据审计（重要发现：假基线实际没走到合格分支）

### 3.1 事实

| 项 | 值 | 来源 |
|---|---|---|
| 假基线输出 `chunk_type` | **256 个全是 0**（即全部"未通过质控"） | `工作区/22_基线/fake_smoke_20261110_verified/chunk_type.npy`（本次逐元素解析） |
| 生成器 v1 的信号量级 | 基线 80~160（pA 量级），tail std **3.0~19.5** | `工作区/40_工具/baseline/gen_fake_npy.py`（v1）；本次复算 `batch4_chunk5000.npy` |
| SDK 的质控阈值 | 尾部 500 点：**std ∈ [0.1, 1.3]**、**过零率 ≤ 23.3%** → 通过记 `chunk_type=1` | `include/rta_basecall.h:34-40`；`src/utils/utils.cu:197-208`（ZCR）、`:302-350`（判定） |
| v1 数据的实测 | tail std 3.06~21.2 → **必然超上界**；ZCR 8%~51% | 本次复算 |

### 3.2 这意味着什么（要如实写进报告）

1. 假基线证明的是**内存分配、H2D 拷贝、TRT 加载、计时链路**通，**没有**证明"合格 chunk 的完整业务分支"通；
2. 更关键的推论：**SDK 期望的输入是归一化信号（约 0~1 量级），不是原始 pA**。这是从阈值反推出来的强约束 —— 如果真实 .ccf 转出来是 pA 量级，**所有真实数据都会被判不合格**。所以 `.ccf → npy` 的归一化规则（C-02）不只是"最好有"，而是**决定真基线是否成立**。
3. 任何"用开源/合成数据造测试集"的方案，**第一道门必须是质控通过率**，否则连有效业务分支都没走到。

### 3.3 已完成的修复（本次）

`工作区/40_工具/baseline/gen_fake_npy.py` 升级为 **v2**：

- 新增 `--profile qc_pass`（默认）：生成"类 Dorado 归一化"信号（分段常数电平 + 电平滞留 + 慢漂移 + 小噪声 + 5 点平滑），逐行标定尾部 std 到 0.18~0.55；
- 内置**与 kernel 等价**的质控自检（std / median / ZCR / chunk_type），未 100% 通过直接 `exit 2`，拒绝产出"看起来像数据但过不了门"的文件；
- `--profile raw_pa` 保留 v1 行为，可复现旧假基线（并明确标注"全部不合格"）；
- manifest 增加 `qc` 段（通过率、std/zcr 极值），报告可直接引用。

**自测结果**（本机，batch=256，5 个种子）：通过率均 **100%**，std ∈ [0.18, 0.55]，ZCR ∈ [0.2%, 17.8%]（阈值 23.3%）。样本：`工作区/50_临时/fake_data/fake_v2_qc_batch8.npy`（sha256 `6181829085ec…99ccb`，8/8 通过，std 0.276~0.526，ZCR 1.8%~5.0%）。

> 注意：合成数据**永远只写"链路/性能/对拍"用途**，报告 R0 必须标 `data_origin=synthetic` 并附质控通过率；不得用 100% 通过率暗示"接近真实"。

## 4. 数据分层：哪一层可以用开源数据替代

| 层 | 内容 | 开源替代 | 可用度 | 说明 |
|---|---|---|---|---|
| **L1 原始信号** | `float32 [N, 5000]`，5 点/步 → T=1000 | ONT 公开 fast5/pod5 等 | **高（工程用途）** | 能覆盖质控/clip/编码器/端到端链路与吞吐；**能**做 P-03~P-07 的 NPU↔GPU 同输入一致性对拍（与信号来源无关）；**不能**产出有生物学意义的 mapping/identity 精度数字（化学体系+模型不匹配） |
| **L2 编码器输出** | `float32 [N, T, 4096]`（NTC） | openfish 预计算 scores/blob（Dorado koi 语义，sup 档 C=4096） | **很高（对拍用途）** | 解码器移植的天然金标准；与信号无关，可完全脱离甲方数据先行 |
| **L3 加密模型** | `.engine` + calib | 不可替代 | **0** | 客户模型是唯一精度来源；开源权重（slorado/dorado）模型结构/许可均不适用 |
| **L4 甲方真件** | 28 个 `.ccf`（6 物种，MD5 锁定） | 不可替代 | **0** | 合同 §3.1：数据由甲方提供、MD5 定唯一性；验收唯一数据源 |
| **L5 参考/真值** | 参考基因组、GIAB truth | GRCh38/T2T、HG002 公开 | **中** | 只用于 P-01/P-02 的 mapping 口径；具体口径待甲方确认（C-07） |

**推论**：开源数据能把"阶段三/四"（解码迁移对拍）从"等甲方"变成"现在就能做"，但对"阶段二真基线"和"阶段五精度"没有替代作用。

## 6. 关键约束与坑（按严重度）

| # | 坑 | 后果 | 规避 |
|---|---|---|---|
| 1 | **归一化未知**（最关键） | 用 ONT 原始 int16/pA 直接转 npy → 质控全 0，或静默喂错分布 → 精度结论不可信 | 质控阈值（std∈[0.1,1.3]）作为**硬门**；向甲方索取 `.ccf` 归一化公式（C-02）；转换器输出必过 QC 自检 |
| 2 | 采样率 / chunk 语义未知 | 5000 点/1.25s？补零/有效长度规则不同 → 边界效应污染 | 索取单加问：采样率、位深、chunk 切分与补零、`chunk_valid_len` 语义 |
| 3 | 化学体系/模型不匹配 | 开源信号过客户模型 → 输出无生物学意义 | 只做工程/对拍，**禁止**任何 mapping/identity 数字出现在开源数据上 |
| 4 | 许可 | ONT CC BY-NC 不可商用/再分发；openfish 含 ONT-PL | 数据与权重不进交付包；法务结论并入 docs/07 §7.2 |
| 5 | 网络/体积 | 本机无 HTTPS；pod5 动辄 GB 级 | 浏览器/目标机下载；只取小子集（<500 MB）；分片+sha256 |
| 6 | 用途混淆 | 把"工程回归数据"写进验收证据链 | 目录/命名隔离：`data/fake/`（合成）、`data/oss/`（开源）、`data/real/`（甲方，只读）；报告 R0 增加 `data_origin` 与 `qc_pass_rate` |

## 8. 判定口径（写进评测规范的一句话）

> **验收精度只认"甲方 28 个 .ccf + MD5 + 同数据 4090 参考"三件套**（acceptance_v0.2 §3.1、§4.2）。
> 开源/合成数据只允许出现在**工程回归与对拍**章节（P-03~P-07、S-01~S-09、T-01~T-03），且报告必须标注 `data_origin ∈ {synthetic, oss, real}` 与 `qc_pass_rate`。
