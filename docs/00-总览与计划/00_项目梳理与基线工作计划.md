## 1. 一页结论（TL;DR）

**项目是什么**：把客户（MGI）的 `ms_basecall` / `cudacall` 碱基识别 SDK —— 一套 **CUDA + TensorRT + 闭源 fast_decode** 的 GPU 工程 —— 迁移到 **华为昇腾 Ascend 910B**（CANN 9.1.0 / torch_npu 2.10 / Ubuntu 22.04），并在 **甲方 4090 结果**上对齐验收指标。

**现在卡在哪**：当前阶段目标是「跑基线」，但基线链路所需的输入只有源码类就位（30 项缺口完整台账见 `01_就位清单与责任矩阵.md`）：

| 基线必需输入 | 状态 | 阻断程度 |
|---|---|---|
| 甲方原始工程（CUDA 版源码） | ✅ 已就位（`工作区/10_源码/baseline_cuda_ms_basecall-main`，245 文件/27 目录） | — |
| **到 GPU/NPU 机器的网络通道** | ❌ **本机实测：`<GPU_HOST>:22`（A800）与 `<CLIENT_HOST>:22`（甲方 4090）TCP 超时、ICMP 不通；910B 地址资料中不存在** | **第一硬阻断：任何基线都跑不了** |
| 甲方 MD5 锁定测试数据（28 个 `.ccf` / 6 物种） | ❌ 未就位（`21_数据/` 为空） | **硬阻断：两条基线都跑不了** |
| `.ccf` 格式规范 / `→npy` 转换规则 | ❌ 未就位（全仓 `ccf` 0 命中，SDK 入口是 `float**`） | **隐藏阻断：数据到手也喂不进 SDK** |
| 编码器模型文件（`rnn_ctc_crf_256_5000_sim_fp16` 等）+ ONNX 源 + calib json | ❌ 未就位（仓库无 `models/`） | **硬阻断：编码层无法推理、无法导出 `.om`** |
| 解密密钥 | ✅ **已就位**：32 字节字面量硬编码于 `common.cpp:19-20` | 不需索取；但违反合同"不得硬编码敏感信息"，交付前须外置 |
| 闭源 `fast_decode` 二进制（`.so`）+ 4 个 `host_*` ABI | ⚠️ 只有头文件（74 行），`.so` 未就位 | 阻断 CUDA 基线解码段与 V0 语料 |
| 迁移版源码（acl_help / om_runtime / fd_host / AscendC kernel） | ❌ 本包内 12/13 类文件级缺失，需确认在谁手上 | 阻断 NPU 侧一切工作 + 决定 93/184 人天口径 |
| 910B 机器 + CANN 9.1.0 | ❓ 无地址；CANN 9.1.0 安装包直链已实测可下（1.21 GiB） | 阻断 NPU 基线 |
| 验收指标口径（identity / Q_Read_Mean 定义、性能 M 口径、三档范围、模块范围） | ❓ 未确认，且文档存在 8 处口径冲突（见 `01` §6） | 阻断"过线"判定的可信度 |

**三条立即行动**：
1. **今天就发函**（`01_就位清单` §7 已备好可直接粘贴的单页）：数据+格式规范、模型+ONNX 源+calib、`fast_decode.so`、**网络通道与 910B 地址**、验收口径 4 项。
2. **D+1 内定性迁移版源码**：文档（`原始资料/19` §8、`原始资料/24`）称源码层「已完成 ~91 人天」，但**交付包内是未迁移的原始 CUDA 版**（`repo_audit.md` 已逐项实证）。回收 → 93 人天口径；否则 → 184 人天、80 人天关键路径复活。
3. **可并行准备的部分今天就动手**（不依赖任何未就位输入）：工作区规范与清单工具（✅ 已完成）、openfish/libsodium/pybind11 下载、CUDA 基线执行手册与验收脚本骨架、`.ccf→npy` 转换器骨架、源码静态修复（`-DSM=89` 等 12 项构建风险）。

## 4. 「跑基线」到底是什么：定义、链路与产物

基线不是一件事，而是 **两条链路 + 一套对拍口径**。当前所有缺口都必须映射到这条链路上，才能判断"缺什么、卡在哪"。

### 4.1 链路 L0：GPU 基线（权威，必须在 4090 上产出）

```
甲方 MD5 数据(.ccf) ──► cudacall(CUDA 版) ──► 输出 npy(sequence/qstring/moves/chunk_type)
        │                      ▲                        │
        │               加密 .engine + fast_decode.so     ├──► 参考 .npy  （验收对比基准）
        └── MD5 校验          + libsodium + TensorRT      └──► 录制 post 语料（V0/V1 解码对拍金标准）
```

- **产物（必须入库并锁定）**：6 物种 × 指定文件（28 条 MD5）的 `sequence / qstring(Phred) / moves / chunk_type` npy；解码中间量 `post` 语料（NTC fp16）；每个产物的 MD5/SHA256 清单。
- **权威性**：验收 diff 口径是「与 4090 结果比」（`acceptance_v0.2.txt:31`），所以 **A800 上跑出来的只能叫"练兵基线"**，不能作为验收基准；但可先验证数据链路、脚本、格式正确。
- **本机做不了**：本机是无 git/cmake/无 WSL distro 的 Windows 办公机，无法编译 CUDA 工程；L0 必须在 Linux GPU 机执行（A800 或甲方 4090）。

### 4.2 链路 L1：NPU 基线（迁移版在 910B 上跑，与 L0 对拍）

```
同一份 .ccf ──► 迁移版(acl+om+AscendC) ──► 输出 npy
                      ▲
        三档 .om（ATC 导出） + AscendC .o + CANN 9.1.0 + torch_npu
```

- 对拍层级：V0（openfish CPU vs 录制 post，锁算法差异）→ V1（逐 kernel vs CPU golden）→ V2（整体 vs 旧 CUDA）→ V3（端到端 vs 4090，三档）。
- 门槛：Modal identity diff < 0.005%、Q_Read_Mean diff < 0.03、单卡 ≥8.5M samples/s、7×24h 稳定。

### 4.3 基线阶段的「最小可开工集」

| # | 输入 | 用途 | 缺了会怎样 |
|---|---|---|---|
| 1 | 28 个 `.ccf` + MD5 | 所有基线与验收的唯一数据源 | 全线停摆 |
| 2 | 编码器模型（至少 sup 档，最好三档）+ 解密密钥 | L0 编码、L1 .om 导出 | 无法出 logits，解码无输入 |
| 3 | `fast_decode.so`（CUDA 版） | L0 解码 + V0 录制语料 | L0 只能出 logits，不能出 sequence |
| 4 | 迁移版源码仓库 | L1 全部 | NPU 侧无法启动 |
| 5 | 910B 机器 + CANN 9.1.0 | L1 运行 | 只能离线桩验证 |
| 6 | 4090 机器访问（或甲方代跑） | L0 权威基线 | 验收基准缺失 |

### 6.2 四类文件的归属原则

| 文件性质 | 放哪 | 规则 |
|---|---|---|
| 我们自己生成的过程文件 | `工作区/60_过程/`（调研、日报、问题登记、实验记录） | 按模板写，带任务 ID，可追溯 |

### 6.3 标准化工程要素

- **ID 体系**：`T-xxx` 任务、`REQ-xxx` 业务必须提供、`DLD-xxx` 可先行下载、`DEP-xxx` 依赖缺口、`EXP-xxxx` 实验记录、`ISS-xxx` 问题。
- **命名**：日期 `YYYYMMDD`，版本 `vX.Y`，基线产物 `<链路>_<物种>_<文件>_<日期>.npy`。
- **清单即契约**：每个输入目录/基线产物目录都要有 `*.manifest.json`（MD5+SHA256+大小），用 `40_工具/manifest/` 生成与校验；验收时直接复算。
- **只读约定**：`原始资料/`、`00_原始解包/`、`21_数据/` 任何情况下不修改；解包/整理只在 `10_源码`、`40_工具` 里做。
- **版本管理**：本机无 git（见 §7），源码版本管理在 Linux 目标机或 GitLab 上进行；本地用 manifest 快照兜底。

## 7. 本机现状（实测，决定"哪些活只能远程做"）

| 项 | 实测结果 |
|---|---|
| OS | Windows 11 办公机，沙箱 workspace-write，工作区 `~/sandai` |
| 构建工具链 | **无** git、cmake、编译器（无 MSVC）、node/npm、docker；WSL 已装但**无发行版** |
| Python | WindowsApps 存根不可运行；可用的是 DSH 内置 Python 3（仅供本地小工具） |
| 可用工具 | ssh/scp（OpenSSH 9.5p2）、curl 8.14.1、7-Zip 26.00、tar、PowerShell **5.1**（无 pwsh 7） |
| 磁盘 | C: 101.9 GB / D:（工作区）**154.9 GB 剩余** / E: 170.9 GB 剩余 |
| GPU / NPU | 无 `nvidia-smi`、无 `npu-smi`、无 `ASCEND_HOME`、无 CUDA |
| 外网 | DNS/TCP:443/HTTP:80 全部可达（GitHub/PyPI/昇腾社区/甲方 GitLab 内网 <GITLAB_IP>）；但**沙箱内 HTTPS 客户端被本地安全栈拒绝**（curl exit 35），下载需目标机或浏览器 |
| 内网到 GPU/NPU | ❌ `<GPU_HOST>:22`（A800）、`<CLIENT_HOST>:22`（甲方 4090）**均 TCP 超时、ICMP 不通**；910B 无地址 |
| 代理/VPN | 系统代理未启用；装有 GlobalProtect（服务运行中，隧道是否建立未验证） |

**推论**：
1. 本机定位＝资料中心 + 计划/文档 + PowerShell/Python 小工具 + 远程操作入口；**CUDA 基线、CANN 编译、NPU 运行必须在 Linux 服务器完成**，"可先行下载"的落地位置是目标服务器。
2. **但当前所有服务器都连不上**（见上表），因此"跑基线"在通道打通前物理上不可能——这一步必须先由业务/客户解决（VPN/专线/跳板），否则后面的数据/模型到位也无处可跑。
