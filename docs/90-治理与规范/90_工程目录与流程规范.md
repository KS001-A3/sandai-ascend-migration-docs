# 90 · 工程目录与流程规范（索引 + 决策记录）

> 版本：v0.1（2026-11-10）｜规范正文（唯一准则）：`README.md`｜实测证据：`调研记录`
> 本文只记录**为什么这样划分**、**四类文件边界**、**标准化清单**，避免规范散落在多个文件里各说一套。

---

## 1. 设计目标

1. **输入不可污染**：HDJY 资料、模型、测试数据必须只读，任何实验不得就地改写。
2. **过程可追溯**：每个结论能追到「谁、什么时候、用什么输入（校验值）、跑了什么命令、得到什么结果」。
3. **工具可复用**：多人反复用的（校验/对拍/构建/验收）集中管理；一次性的放临时区，允许随时清空。
4. **交付可打包**：`docs/` 是对外可交付层，`archive` 是里程碑快照层，两者不混。
5. **大文件不进版本库**：模型/数据/基线产物用「清单（MD5/SHA256）+ 只读目录」管理，而不是塞进 git。

## 4. 本机工具链限制（影响规范执行方式）

| 事实 | 影响 | 应对 |
|---|---|---|
| 无 `git`、无 `cmake`、无编译器、无 WSL 发行版 | 本机不能构建/不能版本管理源码 | 源码版本在 Linux 目标机或 内网代码托管；本地只用 manifest 快照 |
| 只有 Windows PowerShell **5.1**（无 pwsh 7） | 无 BOM 的 UTF-8 脚本在 5.1 下按 ACP=936 解码，中文**行注释**可能吞换行导致语法错误 | 工具脚本：中文只放块注释，代码/输出用 ASCII；或统一 UTF-8 **带 BOM** |
| `ssh`/`scp`/`tar` 可用 | 可远程操作与传输 | 基线执行走 ssh；大产物用 scp + manifest 双校验 |
| Python 仅 内置 3.x | 本地脚本可用，但不是项目运行时 | 项目 Python 环境在目标机（含 torch_npu） |

## 5. 待统决策（规范层面，需 Lead 拍板）

| # | 问题 | 建议 |
|---|---|---|
| 1 | 中文脚本编码：无 BOM（跨平台友好）vs 带 BOM（PS 5.1 友好） | 工具脚本统一 **UTF-8 无 BOM + 中文仅块注释 + 输出 ASCII**（沿用现方案，已验证） |
| 2 | `60_过程` 是否全量进 git（含证据大文件） | 证据文件（manifest、日志）进 git；超过 5 MB 的原始输出只留路径索引 |
| 3 | `docs/` 是否作为唯一交付出口 | 是；`70_存档` 存"某时刻的完整快照"，用于复现，不直接发 HDJY |
| 4 | 模型/数据的备份策略 | 到位后立即双备份（工作区 + 异地/归档盘），并各生成 manifest；损坏可换路径恢复 |

## 6. 使用速查

```powershell
# 生成输入清单（只读输入，清单写到 evidence/）
& '~/sandai/40_工具manifestNew-InputManifest.ps1' `
  -Path '~/sandai/21_数据' `
  -Out  '~/sandai/processevidencedata.manifest.json'

# 校验（HDJY交付后第一件事；退出码 0=通过）
& '~/sandai/40_工具manifestTest-InputManifest.ps1' `
  -Manifest '~/sandai/processevidencedata.manifest.json' `
  -Path '~/sandai/21_数据'

# 环境探查（只读）
& '~/sandai/40_工具envprobe_env.ps1' -Out '~/sandai/processevidenceenv-YYYYMMDD.txt'
```

> PowerShell 5.1 下若脚本被执行策略拦截（本机实测会被拦），用 `powershell -NoProfile -ExecutionPolicy Bypass -File <脚本>` 调用。
